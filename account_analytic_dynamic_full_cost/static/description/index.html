Analytic Dynamic Full Cost

Analytic Dynamic Full Cost

This module extends analytic accounting by introducing an automatic and configurable method to spread reproductive (overhead) costs across productive hourly analytic lines.

It includes the classification of analytic plans as productive, reproductive, or not analyzed.

Functional Purpose

In many organisations, especially cooperatives, service companies and project-based environments, part of the activity generates productive hours (e.g. billable work, project execution), while another part corresponds to reproductive or supporting activity (administration, coordination, infrastructure, shared services…).

Reproductive activity has associated analytic weight. This module distributes that weight across productive branches in each analytic dimension and stores the resulting full-cost amount on analytic lines, producing a more realistic and traceable analytic cost structure.

How Overhead Is Determined

For each analytic line with hours (unit_amount > 0) the module computes:

A reproductive overhead rate for the company and the line date.

A reproductive overhead amount = rate × hours.

A total amount including overhead, stored in a new field

Configurable Time Window

The company parameter Reproductive Overhead Window (days) specifies how many days the system looks back when calculating the overhead rate.

Example:

Window = 365 → overhead based on last year

Window = 180 → last six months

Window = 30 → rolling monthly overhead

This makes overhead time-sensitive and relevant to each analytic line date.

Overhead Rate Formula

For each line dated D, the module considers the period:

[D - window_days, D]

Then computes:

reproductive_rate(D) = sum(amounts on accounts linked to productive plans in period) —————————————————————– sum(unit_amount on accounts linked to productive plans)

If productive hours = 0, the rate is 0. If a line has no hours (unit_amount <= 0), no overhead is applied.

Each analytic line stores:

full_cost_amount = amount + reproductive_rate(D) * unit_amount

This value is available for any analytic report or dashboard.

Automatic Daily Recalculation

A daily cron job recomputes overhead for yesterday’s analytic lines. This guarantees that overhead remains consistent as new reproductive or productive data is posted.

Manual Recalculation

A wizard allows recomputing overhead for any date range, useful when:

the overhead window is changed,

analytic entries are backdated,

reproductive or productive costs change significantly.

Typical Use Cases

  1. Project Costing

Compute a realistic project margin by including its share of indirect costs.

  1. Cooperative / Social Economy Organisations

Distribute coordination or shared service costs transparently across teams.

  1. Internal Hourly Rates Validation

Check whether productive hours carry their proportional overhead share.

  1. Management Accounting / Controlling

Generate richer analytic P&L statements incorporating full-cost methodology.

  1. Forecasting

Integrate overhead allocations into budgets to calculate total cost per hour.

Usage

Usage

This module extends analytic accounting by automatically allocating reproductive overhead on hourly analytic lines.

Overhead is computed from past data and stored directly on each analytic line in the field full_cost_amount.

1. Configure Analytic Plans

Each analytic plan can be marked as:

  • Productive – activity that generates productive hours.
  • Reproductive – supporting/overhead activity whose costs must be spread.
  • Not Analyzed – activity excluded from full-cost analysis together with all descendants.

To configure:

  1. Go to Accounting → Configuration → Analytic Accounting → Analytic Plans.
  2. Open a plan.
  3. Set Full Cost Role to Productive, Reproductive, or Not Analyzed.

Analytic lines derive their full-cost role from the analyzed analytic accounts set on the line. In Odoo's multidimensional analytic model, each root analytic plan has its own account field; dimensions marked as Not Analyzed are ignored.

2. Configure Company Overhead Window

The overhead rate depends on a configurable look-back window (in days).

  1. Go to Settings → Companies → [Your Company].
  2. Set Full Cost Period, Full Cost Weight Basis, and Full Cost Window (Days).
    • Default: 365
    • Meaning: for each analytic line, the module uses the last N days of reproductive costs and productive hours to compute the overhead rate.
Example:
If set to 180, overhead is based on activity in the last 180 days.

3. How Overhead Is Computed

For a given analytic line L with:

  • date = D
  • unit_amount > 0 (hourly line)
  • company window = N days

The module computes:

3.1 Overhead rate

rate(D) =
sum(amount over reproductive accounts in [D-N, D])
-------------------------------------------------
sum(unit_amount over productive accounts in [D-N, D])

If productive hours = 0 → rate = 0.

3.2 Total amount stored on the analytic line

full_cost_amount =
amount + rate(D) * unit_amount

Lines without hours (unit_amount <= 0) keep:

full_cost_amount = amount

4. Automatic Daily Recalculation

A cron job runs daily and recomputes overhead for analytic lines dated yesterday.

This ensures overhead values always reflect the most recent data without manual intervention.

5. Manual Recalculation Wizard

For ad-hoc updates:

  1. Go to Accounting → Analytic Accounting → Recompute analytic full cost.
  2. Select:
    • Company
    • Date From
    • Date To
  3. Click Recompute.

All analytic lines in the date range will be recalculated according to the current overhead configuration.

6. Reporting

You can analyse overhead in any analytic reporting view by using:

  • full_cost_amount
  • full_cost_role (productive/reproductive/not_analyzed)

This allows reporting at analytic account and full-cost role level.
